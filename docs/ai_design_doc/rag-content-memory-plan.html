1. 目标与收益

RAG（检索增强生成）在本项目中的含义：先按语义从 Qdrant 取出与当前任务最相关的 content / memory 片段，再拼进 Prompt，让 LLM 在更小、更准的上下文中生成。

content 内容库 RAG

用户未手选 contentId，或素材描述需要「找对推广主题」时，按广告组/版位/用户草稿语义检索 contents.json，只注入 topK 条相关摘要，而不是空提示或全库硬塞。

memory 长期记忆 RAG

对话与素材生成时，按当前用户问题召回相关偏好（预算习惯、渠道偏好等），替代「按时间取最近 5 条」，减少无关记忆干扰。

维度优化前RAG 优化后
Prompt 体积 内容库常为空或仅 1 条；记忆固定最近 N 条 只注入与 query 相关的 topK（默认 5），token 更省
相关性 记忆与当前问题可能无关（时间排序） 语义相似度排序，问预算召回预算类记忆
素材质量 未选 content 时 LLM 缺少推广语境 自动找到「夏夜专辑」「首发冲刺」等匹配条目
可扩展性 内容/记忆增多后无法全量进 Prompt 向量检索复杂度与库大小近似对数级，可持续增长

2. 现状问题（代码对照）

Content — CreativePromptSuggestService.buildContentLibrary()

// 仅当请求带了 contentId 时取 1 条；否则输出「未指定内容库条目」
if (StringUtils.hasText(contentId)) {
    ContentItem c = contentCatalogRepository.findById(userId, contentId);
    ...
} else {
    contentBlock.append("（未指定内容库条目。）\n");
}

问题：用户没在 UI 选内容库时，推广文案上下文为空，智能描述缺少业务语义。

Memory — LongTermMemoryService.retrieveRelevantMemories()

// 方法签名有 query、topK，但实现忽略 query
List<MemoryEntry> entries = repository.getRecent(userId, topK);

问题：AdAgentOrchestrator 已把用户输入传给 getLongTermContext(userId, query)，但检索仍是时间最近，不是语义最近。

3. 向量库记什么（本方案范围）

type来源文件向量化正文metadata
content data/base/users/{userId}/contents.json name + "\n" + summary user_id, source_id（content UUID）, name
memory data/long_term_memory/{userId}.json 单条 summary user_id, source_id（条目索引或 hash）, created_at

不写入向量库： API Key、效果数字、图片二进制、纯 ID。JSON 文件仍作主数据源与备份；Qdrant 是检索索引层。

5. Content RAG 如何做

1
索引（写入 Qdrant）
应用启动或 contents.json 保存后：读取该用户全部 ContentItem，每条生成 Document，type=content。
2
构建 query
suggest-prompt 时拼接：版位说明 + 用户草稿 + 广告组/计划上下文（若有）作为检索 query；若用户已选 contentId，仍优先精确命中该条，RAG 作补充。
3
检索
filter: user_id == '{userId}' && type == 'content'，topK=5，similarityThreshold≥0.65。
4
注入 Prompt
替换 buildContentLibrary() 输出为「相关推广内容（语义检索）」区块，格式与现有一致，便于 Prompt 模板无感切换。

优化点： 素材 Tab「智能生成描述」在未选内容库时也能自动带上「夏夜氛围」「首发冲刺」等与 query 相关的推广摘要，画面描述更贴业务。

6. Memory RAG 如何做

1
写入双通道
现有 LongTermMemoryRepository.append() 成功后，同步 vectorStore.add(memory Document)。JSON 与向量双写，JSON 便于审计与导出。
2
检索改造
retrieveRelevantMemories(userId, query, topK)：对 query 做 embedding 检索，filter type == 'memory'。
ad-agent.rag.enabled=false 时回退 getRecent()。
3
注入点（不变）
MemoryService.getLongTermContext() → AdAgentOrchestrator.buildEnhancedPrompt() 已在每轮对话注入；素材 Agent 若需用户偏好可同样调用。

优化点： 用户先聊「我预算很紧」再聊「帮我写开屏文案」，第二条会召回预算相关记忆，而不是无关的「上次喜欢信息流」类摘要。

7. 索引同步与隐私

事件动作
应用启动（可选）对配置了索引的用户或全量用户执行 content 全量 reindex（数据量小可接受）
ContentCatalogRepository.save()reindexContent(userId)：删该用户 type=content 向量后重建
LongTermMemoryRepository.append()追加单条 memory 向量
UserPrivacyTools.clearUserLongTermMemory删 JSON + delete filter user_id && type==memory
INTENT_CLEAR_ALL_USER_MEMORY长期记忆向量一并清除（聊天本方案暂不入向量库）

8. 配置与依赖

启动 Qdrant：./scripts/qdrant/start-qdrant.sh

# pom.xml 新增
spring-ai-starter-vector-store-qdrant
spring-ai-rag          # 可选，对话链路后续用 Advisor

# application.yml
ad-agent:
  rag:
    enabled: true
    top-k: 5
    similarity-threshold: 0.65

spring:
  ai:
    model:
      embedding: openai
    openai:
      embedding:
        options:
          model: text-embedding-3-small   # 与 chat 模型分开配置
    vectorstore:
      qdrant:
        host: localhost
        port: 6334
        collection-name: ad_agent_rag
        initialize-schema: true

API Key 仅写在 application-secret.yml（已 gitignore）。Embedding 与 Chat 可用同一 Key，但模型名必须分开；换 embedding 模型需重建 collection。

11. 验收方式

场景操作预期
Content RAG 用户有多条 content；suggest 时不选 contentId，草稿写「夏夜氛围开屏」 Prompt 中出现「夏夜」相关 content 摘要；Qdrant Dashboard 可见 type=content 点
Memory RAG 先对话写入「预算保守」记忆，再问「写文案时注意什么」 长期记忆块出现预算相关摘要，而非无关最近条
降级 ad-agent.rag.enabled=false 或停 Qdrant 应用可启动；content 回退空/单条逻辑；memory 回退 getRecent
隐私 「清除长期记忆」 JSON 删除且 Qdrant 该用户 memory 向量清空
